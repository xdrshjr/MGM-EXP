## Project Overview

- **Type:** Research CLI / evolutionary coding-agent benchmark system
- **Purpose:** Evolve coding agents across a tree of candidate implementations, diagnose failures comparatively, generate child patches, and evaluate them on SWE-bench or Polyglot tasks.
- **Languages:** Python (75 files; about 58% of executable sources), Bash/Slurm (44 files; about 34%), JavaScript/HTML (10 files; about 8%)
- **Frameworks and runtimes:** Python 3.11, Hugging Face `datasets`, OpenAI/Anthropic SDKs, pytest, Apptainer, Slurm, optional local vLLM
- **Primary entry points:** `hgm.py`, `evaluate_agent.py`, `coding_agent.py`, `coding_agent_polyglot.py`, `swe_bench/harness.py`, `polyglot/harness.py`, `polyglot/run_evaluation.py`
- **Configuration:** `config.yaml` for normal SWE/MGM runs; `polyglot_scripts/config_polyglot.yaml` for Polyglot runs; CLI flags override YAML values.
- **Scale:** 242 indexed files, including 75 Python files and 406 public top-level Python functions/classes.

### Execution Model

1. `hgm.py` loads configuration and task data, restores or initializes an evolutionary tree, and selects parent nodes.
2. `hgm_utils.py` chooses strategy A/B/C inputs, launches an isolated self-improvement workspace, and evaluates resulting agents.
3. `self_improve_step.py` and `prompts/` turn one or two task histories/lineages into a structured improvement problem.
4. `coding_agent.py` or `coding_agent_polyglot.py` calls an LLM with edit/bash tools and emits `model_patch.diff`.
5. The SWE-bench or Polyglot harness applies the patch inside Apptainer, runs tests, and writes per-node predictions and `metadata.json`.
6. `hgm.py` appends tree snapshots to `hgm_metadata.jsonl` and continues until the evaluation budget is exhausted.

## Feature Map

### Evolution Engine (`hgm.py`, `tree.py`, `hgm_utils.py`)
Entry: `hgm.py:main()`

- Runs optimistic tree search over coding-agent variants, supports fresh/resumed runs, schedules concurrent evaluation, and persists tree state.
- Implements Mendelian strategy selection: A (single failure), B (two tasks on one node), and C (shared task across lineages).
- **Key exports:**
  - `initialize_run(output_dir, self_improve_llm, tasks, initial_agent_name, ...)` - initialize or restore nodes and submitted-task state.
  - `update_metadata(output_dir, n_task_evals)` - append an accuracy-aligned tree snapshot.
  - `Node` - evolutionary node with descendants, evaluation history, and mean utility.
  - `choose_entry(parent_commit, debug=False)` - select one task for strategy A.
  - `choose_two_entries(parent_commit, debug=False)` - select two distinct tasks for strategy B.
  - `eval_agent(commit_id, tasks=None, ...)` - dispatch a node to the selected benchmark harness and merge results.
  - `sample_child(parent_commit, image_name, ...)` - diagnose, patch, validate, and materialize a child agent.

### Self-Improvement Diagnosis (`self_improve_step.py`, `prompts/`)
Entry: `self_improve_step.py:diagnose_problem()`

- Builds benchmark-aware failure context, asks a diagnosis model for structured JSON, and converts it into the coding agent's problem statement.
- Contains comparative prompt paths for same-node two-task analysis and cross-lineage transfer.
- **Key exports:**
  - `diagnose_problem(entry, commit, root_dir, out_dir, ...)` - strategy A diagnosis.
  - `diagnose_two_entries_same_commit(entries, commit, ...)` - strategy B joint diagnosis.
  - `diagnose_shared_task_two_commits(task_id, commit_primary, commit_context, ...)` - strategy C diagnosis.
  - `get_diagnose_prompt_swe(...)` / `get_diagnose_prompt_polyglot(...)` - assemble single-task prompt context.
  - `get_diagnose_prompt_*_two_entries(...)` and `get_diagnose_prompt_*_shared_task_two_commits(...)` - comparative prompt builders.

### Coding Agents and Tools (`coding_agent*.py`, `tools/`)
Entry: `coding_agent.py:AgenticSystem.forward()`

- Executes the generated repair brief against a temporary Git repository, uses model tool calls to inspect/edit/run commands, and produces a reversible patch.
- `coding_agent_polyglot.py` is the lighter multi-language variant installed as `coding_agent.py` inside Polyglot containers.
- **Key exports:**
  - `AgenticSystem` - owns logging, current diff, regression-test review, and the repair loop.
  - `load_all_tools(logging=print)` - registers the built-in edit and bash tools.
  - `edit.tool_function(command, path, file_text=None)` - view/create/replace text files inside the agent workspace.
  - `bash.tool_function(command)` - execute commands through a persistent bash session.

### LLM and Configuration Layer (`llm.py`, `llm_withtools.py`, `config.py`)
Entry: `llm.py:create_client()` / `config.py:load_config()`

- Normalizes model identifiers and dispatches plain or tool-using conversations across hosted APIs and vLLM-compatible endpoints.
- Extracts robust JSON from imperfect model output and translates tool schemas/history between provider formats.
- **Key exports:**
  - `HGMConfig` and nested dataclasses - typed configuration model.
  - `load_config(config_path="config.yaml", **overrides)` - load YAML and apply dotted overrides.
  - `resolve_llm_model(model)` / `create_client(model)` - select provider and construct a client.
  - `get_response_from_llm(...)` / `get_json_response_from_llm(...)` - non-tool model calls.
  - `extract_json_between_markers(llm_output, required_keys=None)` - recover the last valid structured response.
  - `chat_with_agent(...)` - provider-neutral tool-calling conversation loop.
